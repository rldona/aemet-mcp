# aemet-mcp v0.2.0 🌦️

El paquete deja de ser solo un ejecutable: ahora también se puede **importar como
librería**. Y se corrige el fallo de acentos que apareció en producción.

## ✨ Novedades

- **API de librería.** Además de servidor MCP, el paquete es importable:

  ```ts
  import { AemetClient, buscarMunicipio, areaParaMunicipio } from "@rldona/aemet-mcp";
  ```

  Expone el cliente de dos pasos, municipios (búsqueda y resolución), áreas CAP,
  avisos (tar + CAP XML), estaciones, formateadores y tipos. La entrada es
  `src/lib.ts`, con declaraciones en `dist/lib.d.ts`.

- **`areaParaMunicipio(codigoINE)`** — resuelve el área de avisos CAP (comunidad
  autónoma) a partir del código INE de un municipio, con un mapa provincia → área.

- **`claveAviso(aviso)`** — clave estable de un aviso, para deduplicar.

## 🔧 Corregido

- **Acentos rotos (mojibake) en las respuestas de AEMET.** Su servidor de datos
  devuelve codificaciones distintas según el nodo que conteste —a veces UTF-8, a
  veces doblemente codificado— pero **siempre** declara `charset=ISO-8859-15`,
  así que fiarse de la cabecera no sirve.

  Ahora se decodifica con auto-detección (UTF-8 estricto y, si falla, latin1) y se
  repara el mojibake cadena a cadena después del `JSON.parse`, con
  `reparaMojibake` / `reparaProfundo`.

  Descubierto en producción en notemojes.com: `"AndÃºjar"` en vez de `"Andújar"`.

- **`fetch` obsoleto en runtimes que lo instrumentan.** Se capturaba en el
  constructor, así que un `fetch` parcheado más tarde —Next.js, por ejemplo— no se
  veía. Ahora se resuelve el global en cada llamada.

## 📦 Instalación

```json
{
  "mcpServers": {
    "aemet": {
      "command": "npx",
      "args": ["-y", "@rldona/aemet-mcp"],
      "env": { "AEMET_API_KEY": "TU_KEY" }
    }
  }
}
```
