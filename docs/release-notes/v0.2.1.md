# aemet-mcp v0.2.1 🌦️

Corrección de packaging sobre la [v0.2.0](./v0.2.0.md). Sin cambios funcionales.

## 🔧 Corregido

- **Resolución en CommonJS**: `exports` declaraba solo la condición `import`, así que
  un consumidor que resolviera en CJS (`ts-node`, `jest` en modo CJS, o `tsx` en un
  proyecto sin `"type": "module"`) fallaba al hacer `require()` con:

  ```
  Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: No "exports" main defined ...
  ```

  Se añade una condición **`default`** (catch-all) apuntando al mismo bundle ESM, de
  modo que cualquier runner resuelve el paquete sin que el consumidor tenga que
  tocar su `type`. La resolución ESM (`import`) ya funcionaba.

```jsonc
"exports": {
  ".": {
    "types": "./dist/lib.d.ts",
    "import": "./dist/lib.js",
    "default": "./dist/lib.js"  // 👈 nuevo: fallback para resolución CJS
  }
}
```

> Nota: el bundle es ESM (`type: module`). En **Node ≥ 22.12** `require()` de ESM
> funciona de forma nativa, así que el `default` resuelve y carga sin problema. En
> Node anteriores, un consumidor puramente CJS necesitaría un build CJS aparte (no
> incluido); la vía recomendada sigue siendo `import`.

## 📦 Instalación

```json
{
  "mcpServers": {
    "aemet": {
      "command": "npx",
      "args": ["-y", "@rldona/aemet-mcp"],
      "env": { "AEMET_API_KEY": "TU_KEY" }
    }
  }
}
```
